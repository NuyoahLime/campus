## 2. 三层排行榜体系（已冻结，P0）

| 层级 | 名称 | 数据来源 | 可见范围 | 管理主体 | 标签 |
|------|------|---------|---------|---------|------|
| L1 | 活动项目排行榜 | 某活动中某个项目的有效成绩 | 本校相关用户 | 学校管理员 | AI-DECIDED |
| L2 | 本校排行榜 | 本校各活动/项目/年级/班级的有效成绩 | 本校用户 | 学校管理员 | AI-DECIDED |
| L3 | 平台公开排行榜 | 各校允许公开且审核通过的数据 | 所有人（含访客） | 超级管理员 | AI-DECIDED-FROM-CONFLICT |

> "公开排行榜"统一解释为L3平台公开排行榜。不存在独立于L2和L3之外的第三种排行榜。

## 3. 排行榜可比性规则（已冻结）

### 3.1 活动项目排行榜 L1

- 【AI-DECIDED】 L1必须绑定一个活动项目实例。
- 【AI-DECIDED】 L1中的全部成绩必须来源于同一活动项目、同一项目规则快照。
- 【AI-DECIDED】 不同项目或不同规则快照的成绩不得进入同一个L1排行榜。

### 3.2 本校排行榜 L2

- 【AI-DECIDED】 L2必须绑定一个平台挑战项目。
- 【AI-DECIDED】 默认仅合并规则版本、成绩单位、比较方向一致的活动项目成绩。
- 【AI-DECIDED】 不同规则版本只有在超级管理员明确标记为"成绩口径兼容"后，才允许合并。
- 【AI-DECIDED】 L2可以按年级、班级、性别、活动时间范围等维度筛选，但筛选维度必须保存到排行榜版本快照。
- 【AI-DECIDED】 同一学生跨活动存在多个有效成绩时，默认按排行榜配置选取最好成绩，不直接累计。

### 3.3 平台公开排行榜 L3

- 【AI-DECIDED】 L3必须绑定同一平台挑战项目及兼容规则版本。
- 【AI-DECIDED】 各学校提交的数据必须使用一致的成绩单位和比较方向。
- 【AI-DECIDED】 不满足统一规则口径的数据不得进入同一L3排行榜。
- 【AI-DECIDED】 跨项目综合排行榜不直接比较原始成绩，必须另行配置积分规则或标准化规则。
- 【AI-DECIDED】 V1暂不支持未配置统一积分规则的跨项目综合排行。

## 5. 排行榜定义与排行榜版本（已冻结）

### 排行榜定义

表示一个长期存在的排行榜配置。至少包含：

| 字段 |
|------|
| 排行榜定义ID |
| 排行榜层级（L1/L2/L3） |
| 排行榜名称 |
| 学校或平台范围 |
| 挑战项目 |
| 规则版本兼容范围 |
| 筛选维度 |
| 有效成绩选取规则 |
| 并列规则 |
| 创建人 |
| 创建时间 |
| 当前版本ID |
| 是否启用 |

### 排行榜版本

表示每次计算、生成和发布的结果快照。至少包含：

| 字段 |
|------|
| 排行榜版本ID |
| 排行榜定义ID |
| 版本号 |
| 上一版本ID |
| 状态 |
| 计算参数快照 |
| 数据范围快照 |
| 排名结果快照 |
| 生成时间 |
| 发布时间 |
| 撤回时间 |
| 过期时间 |
| 替换时间 |
| 是否当前公开版本 |
| 创建原因 |
| 关联成绩更正或申诉记录 |

- 【AI-DECIDED】 排行榜定义保存长期配置，排行榜版本保存每次计算和发布结果。
- 【AI-DECIDED】 排行榜更新必须创建新版本，不得修改已发布历史版本的数据快照。
- 【AI-DECIDED】 同一排行榜定义可以有多个历史版本。
- 【AI-DECIDED】 同一排行榜定义最多只能有一个当前公开版本。
- 【AI-DECIDED】 当前版本通过`current_version_id`或等价唯一约束维护。
- 【AI-DECIDED】 L1、L2和L3都采用"排行榜定义 + 排行榜版本"模型。
- 【AI-DECIDED】 L3版本还必须保存所使用的学校数据授权ID集合。
- 【AI-DECIDED】 某项授权撤回后，不影响历史版本内部审计快照，但不得用于新版本。
- 【AI-DECIDED】 对外历史展示必须遵守最新隐私规则。

### 排行榜版本状态（已冻结）

| 状态 | 含义 | 前置状态 | 后续状态 | 操作主体 | 是否终态 |
|------|------|---------|---------|---------|:--:|
| 草稿计算 | 新版本正在计算或等待确认 | 新建版本 | 已生成、已作废 | 系统/对应管理员 | 否 |
| 已生成 | 结果已生成，尚未发布 | 草稿计算 | 已发布、已作废 | 对应管理员 | 否 |
| 已发布 | 该版本已经对目标受众公开 | 已生成 | 已撤回、已过期、已被替换 | 对应管理员/系统 | 否 |
| 已撤回 | 该版本被主动停止展示 | 已发布 | — | 对应管理员 | 是 |
| 已过期 | 该版本超过展示期限 | 已发布 | — | 系统 | 是 |
| 已被替换 | 新版本发布后，该版本不再是当前版本 | 已发布 | — | 系统 | 是 |
| 已作废 | 未发布版本因配置或数据错误被终止 | 草稿计算、已生成 | — | 对应管理员 | 是 |

> ⚠️ 已撤回和已过期不回到草稿计算。需要重新计算时，在同一排行榜定义下创建新版本，初始状态为"草稿计算"，旧版本状态保持不变。

### 新旧版本替换规则（已冻结）

1. 新版本生成后处于"已生成"；
2. 管理员确认发布新版本；
3. 新版本进入"已发布"；
4. 原当前版本自动进入"已被替换"；
5. 排行榜定义的当前版本ID更新为新版本ID；
6. 原版本快照永久保留。

- 【AI-DECIDED】 发布新版本时，原当前版本自动转为"已被替换"。
- 【AI-DECIDED】 不使用"撤回"表示正常版本替换。
- 【AI-DECIDED】 "撤回"只用于主动停止当前版本展示且没有立即发布替代版本的情况。
- 【DEFERRED-P2: P2-RANK-DISPLAY-EXPIRY-001】 排行榜自动过期时间和展示期限规则另行配置。

> ⚠️ 删除"已更新"作为独立状态。更新应生成新版本而非成为状态。
> ⚠️ 有历史版本的排行榜不得物理删除。

### 授权流程

```
学校管理员创建授权草稿 → 提交平台审核 → 超级管理员审核 → 通过后可被L3使用
待审核 → 驳回 → 修改后重提
审核通过 → 学校撤回授权
```

### 授权规则

- 【AI-DECIDED】 学校管理员只能授权本校数据。
- 【AI-DECIDED】 只有审核通过的授权数据才能进入L3。
- 【AI-DECIDED】 超级管理员不能绕过学校授权直接将校内成绩加入L3。
- 【AI-DECIDED】 授权撤回后，不再进入后续新版本。
- 【AI-DECIDED】 已发布历史版本保留内部快照，但对外展示应执行最新隐私授权。
- 【AI-DECIDED】 成绩更正后，旧授权范围仍有效，但必须使用更正后的当前有效成绩生成新版本。
- 【AI-DECIDED】 学校暂停时审核通过的授权自动转为"已暂停"；学校停用时授权自动转为"已撤回"(终态)。不得生成新的L3版本，历史公开版本按平台规则决定是否下架。

### 授权状态流转规则

- 【AI-DECIDED】 学校正常：授权可处于审核通过状态。
- 【AI-DECIDED】 学校暂停：审核通过的授权自动转为"已暂停"。
- 【AI-DECIDED】 学校恢复正常：授权不自动恢复，由超级管理员确认后从"已暂停"转为"审核通过"。
- 【AI-DECIDED】 学校停用：授权自动转为"已撤回"（终态），不可恢复。
- 【AI-DECIDED】 学校重新启用：原已撤回授权不得恢复，必须新建授权记录或授权版本。
- 【AI-DECIDED】 学校暂停时审核通过的授权自动转为"已暂停"；学校停用时授权自动转为"已撤回"(终态)。不得生成新的L3版本，历史公开版本按平台规则决定是否下架。

- 【AI-DECIDED】 已使用该授权生成的历史排行榜版本继续保留审计快照，但公开展示按照最新隐私和生命周期规则处理。
- 【AI-DECIDED】 审核驳回后修改授权范围，应返回草稿并创建新授权版本。
- 【AI-DECIDED】 已撤回授权不得重新变为审核通过。

## Phase4A L2 Ranking Policy Closure

> Policy reference: POLICY-RANKING-L2-BASELINE-001
> Decision document: docs/decision/l2-ranking-policy-baseline-v1.md
> ADR: docs/adr/ADR-015-l2-ranking-policy.md

This addendum freezes the L2 implementation baseline without changing the
v1.2-AI-FROZEN DEC count.

### L2 definition

L2 is a same-school ranking owned by SCHOOL_ADMIN, scoped to one school, and
bound to one ChallengeProject.

L2 is not L1 multiple activity ranking. L2 may consume candidate data from
multiple ActivityProjects under the bound ChallengeProject, but L2 must first
reduce those candidates to one representative candidate per student.

### Effective score and candidate reduction

L2 consumes only Stage26 authoritative effective scores:

```text
score_status = APPROVED
AND is_current_effective = true
```

L2 must not reselect effective ScoreAttempts. L2 cross-activity selection uses
BEST_SCORE only after Stage26 effective-score filtering.

```text
L2_RESELECT_EFFECTIVE_SCORE = NO
L2_CROSS_ACTIVITY_SELECTION_POLICY = BEST_SCORE
CALCULATOR_ONLY_RANKING = YES
```

The L2 candidate reducer chooses the best candidate by frozen RuleVersion
comparison semantics:

| Type | Direction | Representative candidate |
|------|-----------|--------------------------|
| INTEGER | HIGHER_BETTER | MAX(score) |
| INTEGER | LOWER_BETTER | MIN(score) |
| DECIMAL | HIGHER_BETTER | MAX(score) |
| DECIMAL | LOWER_BETTER | MIN(score) |
| DURATION | HIGHER_BETTER | MAX(duration) |
| DURATION | LOWER_BETTER | MIN(duration) |
| GRADE | gradeOrder | Best grade in frozen gradeOrder |

### RuleVersion policy

```text
L2_RULE_VERSION_POLICY = SAME_RULE_VERSION_ONLY
```

L2 v1 does not automatically merge different RuleVersions. SUPER_ADMIN-approved
compatibility is a future policy and implementation extension.

### Filters and time source

```text
SUPPORTED_L2_FILTERS = GRADE, CLASS, ACTIVITY_PERIOD
L2_TIME_FILTER_SOURCE = ACTIVITY_PERIOD
```

Grade uses student_profiles.grade. Class uses student_profiles.class_name.
Activity period uses the execution period of the activity attached to the
ActivityProject. Gender is not supported until an authoritative schema source
exists.

### Visibility and privacy

Anonymous users may read L3 only. Students and School Admins may read L1/L2
only within their own school. Super Admin production-view override is not
implemented for L2 v1.

L2 internal same-school display uses RankingEntry.student_display_name snapshot.
L3 public display remains masked or authorization-controlled.

### Schema policy

```text
L2_DEFINITION_UNIQUENESS = ONE_PER_SCHOOL_PROJECT
SCHEMA_CHANGE_REQUIRED = YES
```

Before L2 creation is enabled in production, the database must enforce the L2
definition uniqueness invariant for one school and one ChallengeProject.
