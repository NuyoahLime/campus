### 成绩数据结构（已冻结）

#### 成绩存储类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 整数型 | 仅允许整数 | 跳绳次数、投中数量 |
| 小数型 | 允许指定小数位数 | 距离、分数 |
| 时长型 | 使用64位整数毫秒存储；展示层转换为秒、分或时分秒 | 跑步时间、完成时间 |
| 等级型 | 按预定义等级编码存储 | 优秀、良好、合格 |

#### 成绩指标类型

| 类型 | 示例 |
|------|------|
| 次数 | 跳绳次数、仰卧起坐次数 |
| 距离 | 跳远距离、投掷距离 |
| 时长 | 跑步用时、任务完成用时 |
| 分数 | 裁判评分、累计积分 |
| 等级 | 优秀、良好、合格、不合格 |

#### 比较方向

| 类型 | 说明 |
|------|------|
| 越大越好 | 数值越大，排名越高 |
| 越小越好 | 数值越小，排名越高 |
| 按等级顺序 | 按预设等级顺序排名 |
| 不排名 | 仅记录结果，不生成排名 |

- 【AI-DECIDED】 等级型项目必须配置完整等级顺序。
- 【AI-DECIDED】 小数型项目必须配置允许的小数位数。
- 【AI-DECIDED】 时长型成绩使用64位整数毫秒存储，排行计算使用毫秒原始值，展示层转换为秒、分或时分秒。不同项目不得使用不同数据库存储单位。
- 【AI-DECIDED】 成绩存储类型、指标类型、单位、比较方向和等级顺序全部进入项目规则版本快照。

## 4. 项目生命周期（已冻结）

### 4.1 项目状态（已冻结）

| 状态 | 含义 | 前置状态 | 后续状态 | 操作主体 | 是否终态 |
|------|------|---------|---------|---------|:--:|
| 草稿 | 项目正在编辑，尚未公开 | 新建 | 已上架 | 超级管理员 | 否 |
| 已上架 | 项目公开可见，可被新活动引用 | 草稿、已下架 | 已下架 | 超级管理员 | 否 |
| 已下架 | 不可被新活动引用，历史活动快照保留 | 已上架 | 已上架 | 超级管理员 | 否 |

- 【AI-DECIDED】 只有草稿状态项目可以删除，且不得存在任何历史业务关联。
- 【AI-DECIDED】 已上架项目的规则修改必须生成新规则版本。
- 【AI-DECIDED】 已下架项目重新上架时可以继续使用原规则版本，也可以先创建新规则版本。
- 【AI-DECIDED】 项目下架不影响历史活动项目快照。

### 4.2 规则版本（已冻结）

- 【AI-DECIDED】 活动引用项目时冻结当时有效的项目规则版本（规则快照）
- 【AI-DECIDED】 项目后续修改不得自动改变历史活动中的项目配置
- 【AI-DECIDED】 下架项目不能被新活动引用
- 【AI-DECIDED】 下架不影响已引用该项目的活动
- 【DEFERRED-P2: P2-PROJECT-RULE-NOTIFY-001】 项目规则变更通知

### 4.3 项目规则版本兼容关系（已冻结）

| 字段 | 规则 |
|------|------|
| compatibility_id | 唯一标识 |
| project_id | 必须是同一个平台挑战项目 |
| source_rule_version_id | 源规则版本 |
| target_rule_version_id | 目标规则版本 |
| compatibility_status | 兼容、不兼容、已失效 |
| score_storage_type | 两个版本必须一致 |
| score_unit | 两个版本必须一致 |
| comparison_direction | 两个版本必须一致 |
| decimal_places | 小数型项目需要兼容 |
| decision_reason | 必填 |
| decided_by | 超级管理员 |
| decided_at | 必填 |
| invalidated_at | 状态为已失效时填写 |

- 【AI-DECIDED】 未建立兼容关系时默认不兼容。
- 【AI-DECIDED】 只允许同一项目的不同规则版本建立兼容关系。
- 【AI-DECIDED】 存储类型、成绩单位或比较方向不同，不得标记为兼容。
- 【AI-DECIDED】 兼容关系由超级管理员确认。
- 【AI-DECIDED】 已失效关系不得用于新的排行榜版本。
- 【AI-DECIDED】 历史排行榜版本保留兼容关系快照。
