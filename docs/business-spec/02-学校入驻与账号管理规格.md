## 1. 学校入驻流程（已冻结）

```
访客填写申请 → 提交 → 超级管理员审核 → 通过 / 需补充 / 驳回
```

### 1.1 入驻申请

| 属性 | 说明 |
|------|------|
| **发起角色** | 【SOURCE-CONFIRMED】 访客（PDF 4.1.1） |
| **前置条件** | 【AI-DECIDED】 申请人无需预先拥有平台账号 |

| 字段 | 是否必填 | 标签 |
|------|:--:|------|
| 学校名称 | 必填 | AI-DECIDED |

| 学校类型 | 必填 | AI-DECIDED |
| 所在地区 | 必填 | AI-DECIDED |

| 证明材料 | 必填 | AI-DECIDED |

#### 学校统一识别规则（已冻结）

- 【AI-DECIDED】 学校统一识别类型包括：统一社会信用代码、学校标识码、教育主管部门登记编码、其他人工核验标识。
- 【AI-DECIDED】 具备统一社会信用代码或学校标识码的学校，必须填写对应编码。
- 【AI-DECIDED】 无统一识别编码的学校，由超级管理员人工核验并生成平台内部唯一学校编码。
- 【AI-DECIDED】 学校名称不得作为唯一去重依据。
- 【AI-DECIDED】 有效学校记录以"统一识别类型 + 统一识别编码"为优先唯一键。
- 【AI-DECIDED】 学校统一识别编码在平台学校主表中全局唯一。
- 【AI-DECIDED】 学校停用后重新入驻时，应恢复或重新启用原学校记录，不得创建新的学校主记录。
- 【AI-DECIDED】 学校合并、拆分或编码变更必须通过专门的学校信息变更记录处理。
- 【AI-DECIDED】 平台内部唯一学校编码一经生成不得复用。

#### 入驻申请状态（独立于学校状态）

| 状态 | 含义 | 前置状态 | 后续状态 | 操作主体 | 是否终态 |
|------|------|---------|---------|---------|:--:|
| 草稿 | 申请人尚未提交 | — | 已提交 | 访客（申请人） | 否 |
| 已提交 | 等待超级管理员审核 | 草稿、需补充 | 需补充、已通过、已驳回、已撤回 | 超级管理员 | 否 |
| 需补充 | 审核人要求补充资料 | 已提交 | 已提交、已撤回 | 访客（申请人） | 否 |
| 已通过 | 入驻审核通过，已创建学校记录 | 已提交 | —（转入学校状态机） | 超级管理员 | 是 |
| 已驳回 | 入驻申请被驳回 | 已提交 | —（可重新提交新申请） | 超级管理员 | 是 |
| 已撤回 | 申请人在审核完成前主动撤回 | 已提交、需补充 | — | 访客（申请人） | 是 |

冻结流转：

```
草稿 → 已提交
已提交 → 需补充 / 已通过 / 已驳回 / 已撤回
需补充 → 已提交 / 已撤回
```

| 字段 |

#### 三种审核结果

| 结果 | 后续动作 | 标签 |
|------|---------|------|
| **审核通过** | 创建学校记录（待启用状态）→ 超管手动创建首任校管账号 → 通知申请人 | AI-DECIDED |
| **需补充材料** | 申请人修改后重新提交 | AI-DECIDED |
| **驳回** | 通知原因，允许重新申请 | AI-DECIDED |

#### 去重与信息修改

- 【AI-DECIDED】 系统优先根据学校统一识别编码进行精确去重。
- 【AI-DECIDED】 无统一识别编码时，根据学校名称、所在地区和学校地址进行重复提示，由超级管理员人工确认。
- 【AI-DECIDED】 驳回后允许修改重新提交，不限次数
- 【DEFERRED-P1: P1-SCHOOL-DUPLICATE-SIMILARITY-001】 系统根据名称相似度提示重复，超管人工检查
- 【AI-DECIDED】 关键学校信息修改需超管处理；非关键信息可由校管修改

## 2. 学校状态（已冻结）

| 状态 | 含义 | 前置状态 | 后续状态 | 操作主体 | 是否终态 |
|------|------|---------|---------|---------|:--:|
| 待启用 | 审核通过并已创建学校，但管理员配置尚未完成 | （入驻通过创建） | 正常 | 超级管理员 | 否 |
| 正常 | 学校可正常开展业务 | 待启用、暂停 | 暂停、停用 | 超级管理员 | 否 |
| 暂停 | 暂时限制新增业务，可处理必要存量事项 | 正常 | 正常、停用 | 超级管理员 | 否 |
| 停用 | 学校账号禁止登录，历史数据保留 | 正常、暂停 | 待启用 | 超级管理员 | 否 |

冻结流转：

```
待启用 → 正常
正常 → 暂停 / 停用
暂停 → 正常 / 停用
停用 → 待启用
```

### 状态影响规则

- 【AI-DECIDED】 正常状态学校可使用全部已授权功能。
- 【AI-DECIDED】 暂停状态学校不得创建新活动、录入新成绩或发布新内容。
- 【AI-DECIDED】 暂停状态下可由学校管理员处理待审核成绩、申诉及必要数据导出。
- 【AI-DECIDED】 停用状态下学校账号禁止登录，历史活动、成绩、审核记录和申诉记录继续保留。
- 【AI-DECIDED】 学校停用后，已公开内容默认转为下架待确认，不直接物理删除。
- 【AI-DECIDED】 超级管理员启用、暂停或停用学校时必须填写原因并生成操作记录。
- 【AI-DECIDED】 学校恢复正常后，原历史数据恢复可访问，但已下架公开内容不得自动重新公开。

### 3.1 学校管理员账号

| 操作 | 操作主体 | 标签 |

| 创建首任校管 | 【AI-DECIDED】 超管手动创建（入驻审核通过后） | AI-DECIDED |
| 创建追加校管 | 【AI-DECIDED】 超管 | AI-DECIDED |
| 编辑/停用 | 【AI-DECIDED】 超管 | AI-DECIDED |
| 多校管 | 【AI-DECIDED】 支持每校多个学校管理员 | AI-DECIDED |

### 3.1.1 学校管理员最低配置规则（已冻结）

- 【AI-DECIDED】 每所正常运营学校至少配置两名处于正常状态的学校管理员。
- 【AI-DECIDED】 首任校管创建后学校状态保持"待启用"。
- 【AI-DECIDED】 第二名校管激活后，学校才允许转为"正常"。
- 【AI-DECIDED】 首任学校管理员创建后，学校仅可完成基础资料配置，不得启用成绩代录、成绩审核和素材自上传审核功能。
- 【AI-DECIDED】 第二名学校管理员创建并激活后，学校业务功能方可完整启用。
- 【AI-DECIDED】 超级管理员停用校管时，如会导致有效校管少于两人，应阻止普通停用。
- 【AI-DECIDED】 紧急停用可以执行，但学校自动转为"暂停"。
- 【AI-DECIDED】 管理员恢复至两人后，由超级管理员恢复学校状态。
- 【AI-DECIDED】 停用学校管理员时，不得导致学校正常管理员数量低于两名；特殊停用由超级管理员执行并生成风险记录。

### 3.4 账号状态机（已冻结）

| 状态 | 含义 | 前置状态 | 后续状态 | 操作主体 | 是否终态 |
|------|------|---------|---------|---------|:--:|
| 待激活 | 已创建但尚未完成首次激活 | — | 正常、停用 | 对应管理员/用户 | 否 |
| 正常 | 可正常登录和使用授权功能 | 待激活、锁定、停用 | 锁定、停用 | 对应管理员 | 否 |
| 锁定 | 因密码、安全或异常行为临时禁止登录 | 正常 | 正常、停用 | 对应管理员/系统 | 否 |
| 停用 | 因毕业、离职、风险或管理原因停止使用 | 待激活、正常、锁定 | 正常 | 对应管理员 | 否 |

冻结流转：

```
待激活 → 正常
待激活 → 停用
正常 → 锁定 → 正常
正常/锁定 → 停用
```

### 账号操作主体

- 【AI-DECIDED】 学生账号、普通老师账号由学校管理员创建、锁定、解锁、停用和重新启用。
- 【AI-DECIDED】 学校管理员账号由超级管理员创建、锁定、解锁、停用和重新启用。
- 【AI-DECIDED】 超级管理员可以在重大安全风险下紧急锁定或停用师生账号，但必须记录原因并通知对应学校管理员。
- 【AI-DECIDED】 系统可以因连续登录失败自动锁定账号，但解锁规则必须配置。
- 【AI-DECIDED】 停用与锁定含义不同，锁定属于临时安全限制，停用属于管理状态变化。
