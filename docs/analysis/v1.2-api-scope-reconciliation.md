## "204个端点"来源分析

API代理报告声称：130个命令 + 74个查询 = 204个端点。该数字是代理**根据每个业务操作推测一个端点**得出的。例如"创建成绩"→1个端点，"审核成绩"→1个端点。这是合理的PROPOSAL级别的估算方法，但：

1. 未经过API设计评审
2. 未考虑端点合并/拆分
3. 未考虑BFF/网关层
4. 未与前端页面需求对齐

**结论**：204可作为API设计阶段的参考起点，但不得作为冻结数字。

## "46个异步事件"来源分析

API代理报告列出了E01-E46共46个通知触发事件。其中约37个可以从S11 §2.2的通知事件清单得到印证（FACT），剩余约9个是代理根据状态转换推测的额外事件（PROPOSAL）。

**结论**：37个通知事件是FACT（来自S11），46个是PROPOSAL（含代理推测）。
