# V1.2 实体口径收敛

> **审计日期**: 2026-07-14 | **任务**: TASK-AUDIT-001

---

## 一、统计口径定义

| 口径 | 定义 | 是否业务事实 | 适用于 |
|------|------|:--:|------|
| **业务对象** (Business Object) | 具有独立身份标识、独立生命周期和独立业务行为的对象 | FACT | 业务需求沟通、状态机定义 |
| **聚合内部实体** | 属于某聚合根内部、不独立对外引用的实体 | PROPOSAL | 领域建模 |
| **版本/快照实体** | 保存不可变历史版本的辅助实体 | PROPOSAL | 数据库设计 |
| **审核记录** | 保存审核操作历史的记录 | DERIVED | 数据库设计 |
| **状态操作记录** | 保存状态变更历史的记录 | DERIVED | 数据库设计 |
| **审计日志** | 系统级操作审计 | DERIVED | 数据库设计 |
| **查询投影** | 为查询优化的只读视图 | PROPOSAL | 数据库设计 |
| **数据库实现对象** | 具体表/视图/物化视图 | PROPOSAL | 数据库物理设计 |

## 三、"32个实体"来源追踪

### 来源

业务域分析代理报告。该代理将以下额外对象计入了实体：

| 额外对象 | 分类 | 说明 |
|------|:--:|------|
| Role | C | 枚举值，非独立对象 |
| EffectiveScore | H | 查询投影，非独立实体 |
| ScoreReviewRecord | F | 审核记录 |
| ProjectMaterial | B | 聚合内部实体 |
| MediaReviewRecord | F | 审核记录 |
| DownloadMaterial | C | 值对象 |
| RankingDetail | H | 查询投影 |

### 32的结论

"32个实体"是**业务对象+聚合内部实体+审核记录+查询投影+值对象的混合计数**。此口径混杂了不同抽象层级。

---

## 四、差异解释

```
32 (代理数) - 25 (注册表宽松数) = 7个差异
```

这7个差异是：
1. Role — 代理计为实体，但规格中为枚举
2. EffectiveScore — 代理计为实体，但规格为逻辑指定
3. ScoreReviewRecord — 代理计为独立，但规格中在Score聚合内
4. ProjectMaterial — 代理单独列出，但规格中属于ChallengeProject
5. MediaReviewRecord — 代理单独列出，但规格中属于Media
6. DownloadMaterial — 代理计为实体，但规格中为平台资源
7. RankingDetail — 代理计为实体，但规格中属于RankingVersion

## 五、推荐统计口径

| 口径 | 数量 | 分类标准 | 适用场景 |
|------|:--:|------|------|
| **A类: 明确业务对象** | **19** | 有独立状态机或独立生命周期的对象 | 业务沟通、状态机定义 |
| **E类: 版本/快照实体** | 3 | ProjectRuleVersion, RankingVersion, ProjectRuleCompatibility | 领域建模 |
| **F类: 审核记录** | 2 | ScoreCorrectionRecord, AbnormalScoreEntry(含审核) | 数据库设计 |
| **G类: 审计/日志** | 1 | AuditLog | 数据库设计 |
| **全部规格提及对象** | 25 | 所有在规格中有明确名称的对象 | 注册表统计 |
| **代理扩展对象** | 32 | 包含审核记录/查询投影/值对象 | **不推荐使用** |

---

## 六、结论

1. **25** 是规格中提到的有名称对象的宽松计数（含版本/审核/审计/值对象）。
2. **32** 是将审核记录、查询投影和值对象也计为独立实体的过度扩展。
3. **19** 是纯"明确业务对象"（有独立状态机或生命周期的核心对象）。
4. **25和32都不得直接用作数据库表数量。** 数据库表数量需要在物理设计阶段确定。
5. **"32个实体"和"25个实体"的统计差异已经解释，两个数字都不代表最终数据库表数量。**
