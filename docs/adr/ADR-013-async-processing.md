# ADR-013: 异步处理

> **状态**: Accepted
> **日期**: 2026-07-14

---

## 背景

系统存在排行榜重算、站内通知、学校状态到授权状态联动和Media到ActivityResult异常标记等需要异步处理的场景。V1不引入消息中间件。

---

## 术语定义

| 术语 | 定义 |
|------|------|
| **Domain Event** | 领域模型表达已发生的业务事实 |
| **Outbox Record** | 与业务事务一起持久化、等待可靠投递/处理的记录 |
| **Task Record** | 描述需要执行的异步工作、重试状态和执行结果 |

三者不得混用。

---

## TECH_DECISION

**V1采用数据库任务表/Outbox语义，不引入MQ。**

| 项目 | 决定 |
|------|------|
| 可靠异步 | 数据库任务表或Outbox Record |
| 写入时机 | 与业务状态变化在同一事务 |
| 处理 | 独立Worker或应用内调度器轮询 |
| 投递 | 至少一次语义 |
| 消费 | 必须幂等 |
| 重试 | 支持重试次数、下次执行时间、失败原因、最终失败 |
| 人工 | 支持人工重放 |
| MQ | V1不引入Kafka/RabbitMQ/Redis队列 |

## 同步 vs 异步边界

**必须同步**（安全检查和业务原子结果）:
- 权限判断
- 学校状态判断
- L3生成时双重检查(ADR-005 §10)
- ActivityApplication批准+Activity创建
- 成绩更正原子业务结果
- Media和ActivityResult聚合内双状态转换

**允许异步**:
- 排行榜重算请求
- 站内通知生成
- 学校状态→授权状态派生同步
- Media状态→ActivityResult异常标记
- 非安全关键的大文件后处理

## @TransactionalEventListener 边界

只能用于: 同进程解耦 + 事务提交后唤醒Worker + 非可靠性关键的辅助动作。不得成为唯一可靠处理机制。数据库任务表才是可靠事实源。

## 拒绝方案

- **方案B(Redis队列)**: V1无Redis
- **方案C(Kafka/RabbitMQ)**: V1规模不需要MQ运维成本
