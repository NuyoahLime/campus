# ADR-012: API合同

> **状态**: Accepted
> **日期**: 2026-07-14

---

## 背景

需要前后端分离的API合同。系统有约16个候选API模块，需要类型安全和可测试的合同。

---

## TECH_DECISION

### API风格: REST

OpenAPI作为HTTP合同事实源，采用后端代码优先生成策略。

| 项目 | 决定 |
|------|------|
| 风格 | REST |
| 合同 | OpenAPI 3.1 |
| 生成 | 后端代码优先(注解+DTO → OpenAPI) |
| CI | 检测生成失败、合同破坏、前端类型生成失败 |
| 前端 | 从OpenAPI生成类型化客户端/类型定义 |
| 版本 | API版本策略在API设计阶段确定 |
| 分页 | 统一分页结构(offset/limit或cursor) |
| 序列化 | ISO 8601时间, 枚举为字符串 |

### 后端约束

- 禁止向接口层暴露JPA实体
- DTO与领域对象分离
- API合同变更必须经过审查
- 破坏性变更遵守版本策略
- 前端不得手工维护重复DTO类型

---

### 错误响应: RFC 9457 Problem Details

不使用`{code, message, data}`统一包装。

**成功响应**:
- 使用HTTP标准状态码
- 返回资源DTO或命令结果DTO
- 列表查询返回统一分页结构
- 201返回Location; 204无内容

**错误响应扩展字段**:
| 字段 | 用途 |
|------|------|
| `errorCode` | 稳定机器可读业务错误码 |
| `traceId` | 日志追踪标识 |
| `fieldErrors` | 字段验证错误 |
| `currentState` | 状态冲突时的当前状态 |
| `allowedTransitions` | 可选, 仅在不泄露权限时返回 |

**HTTP语义** (V1不使用422):
| 状态码 | 场景 |
|:--|------|
| 400 | 请求格式错误、字段类型错误、必填项缺失和基础输入验证失败 |
| 401 | 未认证、Session不存在或已失效 |
| 403 | 已认证但无权限，包括明确的跨校拒绝 |
| 404 | 资源不存在，或按统一安全策略隐藏资源存在性 |
| 409 | 业务状态冲突、并发冲突、幂等冲突 |
| 413 | 上传内容超过限制 |
| 415 | 不支持的媒体类型 |
